# Componentes de Usuarios y Acceso

## Descripción general
Este grupo cubre la gestión de identidades del sistema: la pantalla de login/landing (`Welcome`), el botón de inicio de sesión con Microsoft (`LoginButton`), la administración de accesos a un grupo de Microsoft Entra/Graph (`Acceso`) y el CRUD de usuarios internos de la mesa de ayuda — técnicos, administradores y franquicias (`Usuarios` y sus modales de alta). En conjunto resuelven "quién puede entrar" y "quién existe como usuario/franquicia dentro de las listas de SharePoint que respaldan la app".

## Archivos
- `src/components/Acceso/Acceso.tsx` (`UsuariosApp`): lista paginada y buscable de miembros de un grupo de Microsoft 365 (Graph), con botón para otorgar acceso (abre modal) y acción de eliminar miembro del grupo.
- `src/components/Acceso/OtorgarAcceso/AgregarFranquicias.tsx` (`NuevaFranquicia`): formulario/modal para dar de alta una franquicia (Título, Dirección, Ciudad, Celular, Correo) contra la lista de Franquicias.
- `src/components/Usuarios/Usuarios.tsx` (`UsuariosPanel`): panel con selector "Franquicias / Resolutores / Administradores", tabla filtrable por texto y botón "+" que abre el modal de alta correspondiente; incluye eliminar con confirmación.
- `src/components/Usuarios/AgregarFranquicias/AgregarFranquicias.tsx` (`NuevaFranquicia`): formulario/modal para alta de franquicia — código idéntico al de `Acceso/OtorgarAcceso/AgregarFranquicias.tsx` (ver "Oportunidades de mejora").
- `src/components/Usuarios/AgregarUsuarios/AgregarUsuarios.tsx` (`NuevoTecnico`): formulario/modal para alta de técnico o administrador (Nombre, Correo), fijando el campo `Rol` según la prop `tipo`.
- `src/components/LoginButton/LogiButton.tsx` (`LoginButton`): botón que dispara `signIn()` (MSAL) mostrando estado de carga ("Abriendo Microsoft…").
- `src/components/Welcome/Welcome.tsx` (`SolviAuthLanding`): landing de login con panel izquierdo de anuncios/tips y panel derecho con el CTA de login (usa un `onLogin` propio, no `LoginButton`).

## Flujo del módulo
1. En la landing (`Welcome`) el usuario ve tips públicos (cargados sin sesión vía `obtenerTipsLogOut`) y pulsa "Iniciar sesión", que dispara el `onLogin` pasado por `App.tsx` (flujo MSAL manejado fuera de este componente).
2. Una vez autenticado, un administrador entra a `Usuarios` para gestionar franquicias/técnicos/administradores: filtra con la barra de búsqueda, cambia el `select` de categoría y usa el botón "+" para abrir el modal de alta correcto (`NuevoTecnico` o `NuevaFranquicia` de `Usuarios/AgregarFranquicias`). Al eliminar una fila, `useConfirm()` muestra un diálogo modal genérico antes de invocar `deleteUser`.
3. Por separado, `Acceso` gestiona el grupo de Microsoft 365 (permisos de acceso a la app u otro recurso): lista miembros vía Graph, permite buscar/paginar, otorgar acceso (abriendo el modal de franquicias de `OtorgarAcceso`, aunque el flujo real de "agregar miembro al grupo" — `addMemberByUserId` — está comentado/deshabilitado) y eliminar miembros con `window.confirm` nativo (inconsistente con el `useConfirm` usado en `Usuarios.tsx`).
4. `LoginButton` (`LogiButton.tsx`) es una pieza de UI para iniciar sesión, pero no se encontró ningún importador en `src` fuera del propio archivo: `App.tsx` usa `WelcomeSolvi` con un `handleAuthClick` propio en lugar de este botón (ver hallazgo abajo).

## Dependencias
- **Funcionalidades**: `access/GroupMembers.ts` (`useGroupMembers`), `access/Workers.ts` (`useWorkers`), `access/Franquicias.ts` (`useFranquicias`), `auth/Usuarios.ts` (`useUsuarios`), `content/Anuncementes.ts` (`useTips`).
- **Otros módulos internos**: `src/graph/GrapServicesContext` (`useGraphServices`, inyecta repos/servicios Graph/SharePoint), `src/auth/msal` (`getAccessToken`), `src/auth/authContext` (`useAuth`), `src/Services/GraphUsers.service` (`removeMemberByUserId`, `removeMemberByEmail`), `src/components/ModalDelete/ConfirmProvider` (`useConfirm`).
- **Models**: `src/Models/Tips.ts` (`TipUI`).
- **Librerías externas**: React (hooks, sin librería de formularios); no se usan librerías de UI de terceros en estos archivos (los `<select>`/tablas son HTML plano con CSS Modules/CSS propio).

## Oportunidades de mejora
1. **Duplicación exacta de componente**: `src/components/Acceso/OtorgarAcceso/AgregarFranquicias.tsx` y `src/components/Usuarios/AgregarFranquicias/AgregarFranquicias.tsx` son **idénticos línea por línea** (mismo import `./NuevoUsuario.css`, mismo `useFranquicias`, mismos labels y placeholders, incluyendo el bug de `id="nt-nombre"` repetido en los 4 primeros campos — ver punto 4). Deberían unificarse en un único componente reutilizable en lugar de mantener dos copias que pueden divergir con el tiempo.
2. **Typo de nombre de archivo/componente**: `src/components/LoginButton/LogiButton.tsx` exporta `LoginButton` pero el archivo se llama `LogiButton.tsx` (falta la "n"). Además, la búsqueda en todo `src` no encontró ningún import de este componente: parece código muerto, ya que `App.tsx` implementa su propio botón de login dentro de `Welcome.tsx`/`handleAuthClick`.
3. **Lógica de negocio y llamadas a servicios filtradas en el componente**: `Acceso.tsx` invoca directamente `removeMemberByUserId`/`removeMemberByEmail` de `GraphUsers.service` y calcula el mensaje de error (`errMsg`) con lógica de narrowing de tipos dentro del JSX/componente, en vez de delegarlo a un hook de `Funcionalidades` como hacen el resto de pantallas (`useUsuarios`, `useFranquicias`). Esto rompe la consistencia arquitectónica UI/Funcionalidades del resto del proyecto.
4. **Bug de accesibilidad/HTML**: en ambos `AgregarFranquicias.tsx`, los campos "Nombre Completo", "Dirección", "Ciudad" y "Celular" reutilizan el mismo `id="nt-nombre"` para su `<input>` y el mismo `htmlFor="nt-nombre"` en la etiqueta — solo el último campo (`Correo`) tiene id propio (`nt-correo`). Esto rompe la asociación label/input para lectores de pantalla y para clic en el label.
5. **Confirmación inconsistente**: `Acceso.tsx` usa `window.confirm`/`alert` nativos para eliminar un miembro del grupo, mientras `Usuarios.tsx` usa el `ConfirmProvider` (`useConfirm`) ya disponible en la app. Debería unificarse a `useConfirm` para una UX consistente y testeable.
6. **Manejo de error/carga superficial**: en `Acceso.tsx`, si `removeMemberByUserId` falla se hace `console.error` + `alert`; no hay estado de error persistente en la UI (a diferencia de `useGroupMembers` que sí expone `error`). En `Usuarios.tsx` no hay manejo de error alguno para `useUsuarios`/`useFranquicias` (solo loading), y el mensaje "No hay usuarios para los filtros seleccionados" se muestra también cuando `loading` es `true`, lo cual es confuso (debería mostrar un estado "Cargando…" separado).
7. **Prop sin uso**: `Welcome.tsx` declara `announcements?: TipUI[]` en `SolviAuthLandingProps` pero nunca la destructura ni la usa en el render (usa `tipsUI` del hook `useTips` en su lugar) — prop muerta que puede eliminarse o cablearse.
8. **Selector de tamaño de página con una sola opción**: en `Acceso.tsx`, `<select>` de "Filas por página" solo tiene `<option value={5}>5</option>`, por lo que `setPageSize` nunca puede cambiar a otro valor real desde la UI (funcionalidad incompleta).
